# 双店部署清单(K-DEP-1)

> 2026-10-24。目标形态:同一台服务器(Debian)承载两个独立店铺,不同域名,共享图库目录;商品主从同步(jerseyshelf 主店 → KITVAULT 卫星店)。边界见《开发执行文档》§12.1:只共享图库与商品资料,订单/账号/支付/物流零共享。

## 1. 进程与端口规划

| 服务 | 目录 | 端口 | 进程管理 |
|---|---|---|---|
| jerseyshelf 主店 | `/srv/jerseyshelf`(现有) | 127.0.0.1:3001 | systemd `jerseyshelf.service`(已有,不动) |
| jerseyshelf 图搜 Python | `/srv/jerseyshelf/scripts/image-search` | Unix socket | systemd(已有) |
| KITVAULT 前台 | `/srv/kitvault/apps/web` | 127.0.0.1:3000 | systemd `kitvault-web.service`(下文) |
| KITVAULT 后台 | `/srv/kitvault/apps/admin` | **127.0.0.1:3002** | systemd `kitvault-admin.service`(下文) |
| 共享图库 | `/srv/media` | — | 两店只读写文件,不监听 |

KITVAULT admin 默认 3001 与主店冲突 → **启动命令固定 `-p 3002`**(systemd 内指定,代码不用改)。

## 2. 目录结构(保持仓库相对布局)

KITVAULT 整仓 rsync 到 `/srv/kitvault`,**保持相对结构**(数据访问层按 `process.cwd()/../../` 解析,`cwd` 为各 app 目录):

```
/srv/kitvault/
├── apps/web/           # next start 的 cwd
├── apps/admin/         # next start 的 cwd(-p 3002)
├── packages/db/prisma/dev.db   # SQLite 库(先本地迁移好再上传,或服务器上跑迁移脚本)
├── data/               # settings.json 等文件 + 旧 JSONL(只读保留)
├── shared-media/       # 开发默认;生产建议软链 → /srv/media
└── node_modules/       # 生产依赖(服务器 npm ci --omit=dev 后 prisma generate)
```

生产挂载共享图库二选一:
- `ln -s /srv/media /srv/kitvault/shared-media`(零配置,推荐);
- 或后台 `/sync` 页填 `sharedMediaDir=/srv/media`。

## 3. systemd 单元(两份,替换 user/路径)

```ini
# /etc/systemd/system/kitvault-web.service
[Unit]
Description=KITVAULT storefront
After=network.target

[Service]
WorkingDirectory=/srv/kitvault/apps/web
ExecStart=/usr/bin/npm run start -- -p 3000
Restart=always
Environment=NODE_ENV=production
# 出网代理(若服务器需代理访问 OMS/翻译源;无则删)
# Environment=HTTPS_PROXY=http://127.0.0.1:7890

[Install]
WantedBy=multi-user.target
```

`kitvault-admin.service` 同构:`WorkingDirectory=/srv/kitvault/apps/admin`、`-p 3002`。
首次部署顺序:① `npm ci` → `npm run build`(仓库根,双站一起)② 上传 `data/`(含 settings.json 密钥配置)③ 若库未随仓,`node scripts/migrate-jsonl-to-db.mjs --write && node scripts/seed-dataset.mjs --write` ④ `systemctl enable --now kitvault-web kitvault-admin`。

## 4. Nginx 双 server 块

```nginx
# 主店(现有配置不动,仅示例对照)
server {
  server_name jerseyshelf.com;
  location / { proxy_pass http://127.0.0.1:3001; }
  location /media/ { alias /srv/media/; expires 1y; add_header Cache-Control "public, immutable"; }
}

# 卫星店(KITVAULT)
server {
  server_name <kitvault-域名>;
  location / { proxy_pass http://127.0.0.1:3000; }
  # 共享图库静态直出,Node 不经手
  location /media/ { alias /srv/media/; expires 1y; add_header Cache-Control "public, immutable"; }
  client_max_body_size 12m;   # 以图搜款上传
}
server {
  server_name admin.<kitvault-域名>;
  location / { proxy_pass http://127.0.0.1:3002; }
  client_max_body_size 12m;
}
```

证书:certbot 分别为三个 server_name 签发。DNS:两域名 A 记录同 IP。

## 5. 同步链路上线(K-S2-5)

1. 主店:完成 S1 出口(`/api/sync/catalog` + 令牌,见主店方案 §四阶段 S);主店 `/admin/sync` 生成令牌。
2. 卫星店:后台 `/sync` 页填 baseUrl + token,`启用同步` 保存;点「立即同步」做首连全量(3736+ 件)。
3. 核对字段与主站实现一致(契约类型见 `apps/web/src/lib/catalog-sync.ts` 顶部;分类映射:主站分类 slug 不在本店 `CATEGORIES` 的会被过滤、兜底 `other`)。
4. 验收(主站方案 §四 S3):改价 ≤10 分钟可见;删除 tombstone 生效(软删,前台 404);拔共享卷走 URL 补拉不重复占盘。
5. 已知差异(K-S2-5 联调时确认):本店 override(价格系数/上下架/文案)在商品**重新同步**时应用;改 override 后想立即生效,等该商品下次内容变更或「立即同步」前清其 syncHash。

## 6. 备份与回退

- 每日备份:`/srv/kitvault/packages/db/prisma/dev.db`(SQLite 单文件,`sqlite3 .backup` 或停机拷贝)+ `/srv/kitvault/data/`(settings.json 是配置与密钥,**与库成套备份**)+ `/srv/media`(只增不删,可低频)。
- 回退:双店独立,任一侧 `git revert` + 重启即回;库回退用备份文件覆盖;同步域数据可 `dbClearSyncProducts`(db-store 内置)一键清除后重同步。
- 端口/域名回退:下线 Nginx 卫星 server 块 + `systemctl stop kitvault-*`,主店不受任何影响。
